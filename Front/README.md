# Front: HYFE 홈페이지 프론트엔드

지금은 **디자인 시안과 디자인 시스템**만 `design/`에 있습니다.

- 파일 구성과 시안 보는 법: [`design/README.md`](design/README.md)
- 이 문서: **어떻게 만들었는지**, **이어서 작업하는 법**

---

## 1. 목표

- **기능:** 기존 사이트(hyfe-website.vercel.app)와 **100% 동일**하게 유지
  - 가입 승인, 로그인, 레포트 게시판, 리크루팅 자료 다운로드
- **바꾸는 것:** 디자인만 새로
- **1순위 방문자:** 외부인(OB, 타 학회, 금융권). 첫 화면만 보고 "금융 전반을 체계적으로 다루는 학회"라고 느끼게 하는 게 목표
- **내용 기준:** **26-2 HYFE 홍보자료**. 기존 사이트와 숫자가 다르면 홍보자료를 따름
  - 설립 2007년
  - 4개 팀
  - 학기별 40~50명
  - 알럼나이 450여 명

## 2. 사용한 도구

| 도구 | 용도 |
|---|---|
| **Claude Code** (VS Code) | 기획 정리, 코드 작성, 브라우저 캡처로 화면 점검까지 전부 |
| **impeccable** 스킬 | 주 디자인 스킬. `init`(사이트 목적 정리) → `shape`(화면 계획) → 구현 순서로 사용. 품질 기준(대비·간격·움직임) 점검 |
| **taste-skill** (`design-taste-frontend`) | 점검용 참고. "AI가 만든 티" 나는 패턴을 거르는 데만 사용 |

두 스킬은 김준형 PC 로컬에만 설치돼 있고, 이 저장소에는 들어 있지 않습니다.

## 3. 작업 순서

**① 레퍼런스 3곳 비교 → 장점만 골라 조합**

| 영역 | 가져온 곳 | 내용 |
|---|---|---|
| 히어로·스크롤 흐름·글씨체 | RISK (riskorea.com) | 머리글자 강조 제목 → **H**an**Y**ang **F**inancial **E**ngineering, 섹션별 바랜 사진 배경, 오른쪽 섹션 목차 |
| 리포트 카드 | KUVIC (kuvic.com) | 홈에 최신 리포트 카드 4개 + More Reports |
| 연혁·모집 버튼 | STOCKWARS (stockwars.net) | 홈 하단 모집 안내 + Join Us |

- 각 레퍼런스의 약점은 피함
  - RISK: 스크롤이 너무 긺
  - KUVIC: 개인 연락처가 공개돼 있음
  - STOCKWARS: 연혁이 글로만 길게 이어짐
- 영문 글꼴: STOCKWARS(Raleway)와 겹치지 않게 Poppins를 쓰고, 메뉴는 전부 대문자로 함

**② 사이트 목적 정리:** [`design/PRODUCT.md`](design/PRODUCT.md)
- 누구를 위한 사이트인지
- 무엇을 앞세울지: "4개 팀으로 금융 전반"
- 지킬 원칙

**③ 공통 부품 먼저 만들기**
- 화면보다 **색·글꼴·간격(토큰)**과 **공통 컴포넌트**를 먼저 만듦
  - 컴포넌트: 버튼, 입력창, 탭, 표, 카드, 배지, 헤더 등 18종
- 파일: [`design/design-system/`](design/design-system/)
- 모든 화면은 이 값과 부품만 사용함

**④ 홈 시안을 고치고 비교하기 반복 (v1 → v11)**
- 매번 레퍼런스와 나란히 놓고 비교함
- 1280 / 1440 / 1536 / 1920px와 모바일(390px)에서 캡처해 확인함

## 4. 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| 메인 색 **한양블루** `#0E4A84` (잠정) | 학교 정체성. 공식 값을 확인하면 `tokens.css` 한 줄만 바꾸면 됨. 오렌지는 "모집 중" 배지에만 사용 |
| 히어로 = **H·Y·F·E 4글자 강조** + 본관 블루아워 사진 | 사진 위에서는 강조 글자를 흰색 100%, 나머지는 반투명으로 함. 한양블루 글씨는 어두운 사진 위에서 묻힘 |
| 홈 순서: HERO → OUR TEAMS → CURRICULUM → REPORTS → RECRUITING | **홈은 요약만** 담음. 섹션이 많고 화면마다 멈추던 초안이 너무 길어서 줄임. 자세한 내용은 각 메뉴 페이지로 보냄 |
| 커리큘럼 = **팀별 펼침 패널** | 4개 팀(리서치·IBD·파생상품·퀀트)이 Lv1 교육 → Lv2 실습 → Lv3 프로젝트 → 결과물 구조임을 한눈에 보여 줌. 표·계단 등 3안을 실제 화면으로 비교한 뒤 고름 |
| 레포트는 주인공이 아니라 **근거** | 현재 사이트에 올라간 레포트가 없고(카페에만 있음), 대부분 리서치팀 것이라 4팀 강점이 가려짐 |
| 사진은 AI 생성 이미지 사용 | 본관 1장 + 팀별 커리큘럼 4장(흰·회·남색 톤). 직접 찍은 사진이 생기면 교체 |
| 메뉴 = 각 페이지로 이동 | HTML에는 실제 주소(`/about` 등)를 그대로 씀. 시안 전용 스크립트만 지우면 Next.js 라우팅에 연결됨 |

**지킬 것**
- 개인 연락처는 공개 페이지에 넣지 않음. 학회 공용 이메일과 인스타그램만 사용
- 면접 후기는 회원 전용
- 숫자와 수상 이력은 확인된 것만 씀

## 5. 이어서 작업하는 법 (Claude로 다른 페이지 만들 때)

Claude에게 먼저 이렇게 시키면 같은 디자인으로 이어집니다.

```
Front/design 폴더의 PRODUCT.md, DESIGN.md, design-system/tokens.css, design-system/components.css를
먼저 끝까지 읽고 그대로 따라줘. 새 색·글꼴·간격 값을 만들지 말고 tokens.css 변수만 써.
기존 사이트(hyfe-website.vercel.app)의 [페이지 이름] 기능은 100% 그대로 두고 디자인만 새로 만들어줘.
mockup/home.html의 헤더·푸터·메뉴를 그대로 재사용해줘.
```

**남은 일**
1. **나머지 페이지 시안:** ABOUT, RECRUITING, REPORTS, 로그인·가입, MEMBER
   - 시안에서 메뉴를 누르면 각 페이지에 들어갈 내용 목록이 보임
2. **홈 내용 정리:** "금융 전반", 팀 설명 문장이 여러 번 겹침
3. **Next.js로 옮기기 → 백엔드 연결:** 가입 승인, 로그인, 게시판, 다운로드
4. **확인할 것**
   - 한양블루 공식 색상 코드
   - 레포트 분류를 4개 팀 기준으로 바꿀지
   - 관리자 화면 캡처(관리자 기능 재현용)
